# EC売上データ分析パイプライン 詳細開発ガイドライン
対象データセット: Olist Brazilian E-Commerce Dataset (抽出4ファイル)

## 1. Bronze層（データ取り込み）
**【担当: データエンジニア (メンバーA)】**
*   **目的:** 外部システムから連携された生データを、欠損等も含めてそのままDeltaフォーマットで保存する。
*   **処理要件:** CSVファイルを読み込み、一切の加工を行わずにDeltaテーブルとして上書き（または追記）保存する。

| 入力ファイル (CSV) | 出力テーブル名 (Bronze) |
| :--- | :--- |
| `olist_orders_dataset.csv` | `bronze_orders` |
| `olist_order_items_dataset.csv` | `bronze_order_items` |
| `olist_products_dataset.csv` | `bronze_products` |
| `olist_customers_dataset.csv` | `bronze_customers` |

---

## 2. Silver層（データクレンジング・構造化）
**【担当: データエンジニア (メンバーA)】**
*   **目的:** 分析に耐えうる品質にデータを整形する（型の変換、不要データの除外、欠損値の補完）。
*   **処理要件:** 以下の表に従い、Bronzeテーブルからデータを読み込み、加工処理を施してSilverテーブルとして保存する。

| 入力 (Bronze) | 出力 (Silver) | 具体的な加工・クレンジング処理要件 |
| :--- | :--- | :--- |
| `bronze_orders` | `silver_orders` | **1. データ型変換:** `order_purchase_timestamp` などの日時カラム（文字列型）を `Timestamp` 型にキャストする。<br>**2. 日付の抽出:** 売上集計用に、注文日時から「注文日(YYYY-MM-DD)」と「注文年月(YYYY-MM)」のカラムを新規作成する。<br>**3. フィルタリング:** `order_status` が `canceled` (キャンセル) と `unavailable` (無効) のレコードを除外する（有効な注文のみ残す）。 |
| `bronze_order_items`| `silver_order_items` | **1. 計算カラム追加:** 商品価格(`price`) と 配送料(`freight_value`) を足し合わせた `total_amount` (総支払額) カラムを作成する。 |
| `bronze_products` | `silver_products` | **1. 欠損値対応:** `product_category_name` がNULLまたは空文字のレコードに対し、値を `"unknown"` (カテゴリ不明) に置換する。<br>**2. カラム除外:** 分析に不要な商品サイズや重量のカラム（`product_weight_g` など）をドロップする。 |
| `bronze_customers` | `silver_customers` | **1. クレンジング:** 特殊な加工は不要だが、分析しやすいように州（`customer_state`）や都市（`customer_city`）の大文字・小文字を統一する（例: 全て大文字にする）。 |

---

## 3. Gold層（ビジネス集計・データマート作成）
**【担当: データアナリスト (メンバーB)】**
*   **目的:** ダッシュボードから直接参照するための、結合・集計済みテーブル（データマート）を作成する。
*   **処理要件:** Silverテーブルを結合（JOIN）し、ビジネス要件に沿った2つの集計テーブルを作成する。

### Goldテーブル①：月別・カテゴリ別売上マート (`gold_monthly_category_sales`)
全体の売上トレンドと、商品カテゴリごとのパフォーマンスを把握するためのテーブル。

*   **結合ロジック (JOIN):**
    *   `silver_orders` と `silver_order_items` を `order_id` でINNER JOIN。
    *   そこに `silver_products` を `product_id` でLEFT JOIN。
*   **集計ロジック (GROUP BY):**
    *   **グルーピングキー:** 「注文年月 (YYYY-MM)」「商品カテゴリ (`product_category_name`)」
    *   **算出する指標 (AGGREGATIONS):**
        *   売上合計金額: `SUM(total_amount)` または `SUM(price)`
        *   注文アイテム数: `COUNT(order_item_id)`
        *   ユニーク注文数: `COUNT(DISTINCT order_id)`

### Goldテーブル②：顧客地域別パフォーマンスマート (`gold_regional_sales`)
どの地域の顧客がアクティブで、多く購入しているかを把握するためのテーブル。

*   **結合ロジック (JOIN):**
    *   `silver_orders` と `silver_customers` を `customer_id` でINNER JOIN。
    *   そこに `silver_order_items` を `order_id` でINNER JOIN。
*   **集計ロジック (GROUP BY):**
    *   **グルーピングキー:** 「顧客の州 (`customer_state`)」
    *   **算出する指標 (AGGREGATIONS):**
        *   売上合計金額: `SUM(total_amount)`
        *   ユニーク顧客数: `COUNT(DISTINCT customer_unique_id)`
        *   顧客あたりの平均購買額: `SUM(total_amount) / COUNT(DISTINCT customer_unique_id)`

## 4. 可視化（Databricks SQL ダッシュボード要件）
**【担当: データアナリスト (メンバーB)】**
Gold層のデータを利用して、ビジネスユーザー向けのダッシュボードを作成する。

1.  **売上推移チャート (折れ線グラフ):**
    *   使用テーブル: `gold_monthly_category_sales`
    *   X軸: 注文年月 / Y軸: 売上合計金額
    *   目的: 全体の売上が上がっているか、下がっているかのトレンドを見る。
2.  **カテゴリ別売上ランキング (横棒グラフ):**
    *   使用テーブル: `gold_monthly_category_sales`
    *   X軸: 売上合計金額 / Y軸: 商品カテゴリ (上位10カテゴリ等でフィルタ)
    *   目的: どの商品カテゴリが売上の主力かを特定する。
3.  **地域別売上分布 (コロプレスマップ or 棒グラフ):**
    *   使用テーブル: `gold_regional_sales`
    *   地域（州）ごとの売上合計、または顧客数を可視化。
    *   目的: ブラジル国内のどのエリアの顧客がビジネスに貢献しているかを確認する。
