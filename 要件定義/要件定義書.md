# 要件定義書：EC売上データ分析ダッシュボード構築プロジェクト

## 1. プロジェクトの背景と目的
現在、我が社のEC事業では、注文データや顧客・商品データがCSVファイルとして蓄積されているものの、それらが統合されておらず、日々の売上トレンドやカテゴリ別のパフォーマンスを迅速に把握できない課題がある。
本プロジェクトは、Databricksを活用してこれらの生データを統合・加工し、経営層やマーケティング担当者が直感的に状況を把握できる「売上分析ダッシュボード」を構築することを目的とする。
また、今後のデータ基盤拡張を見据え、属人化を防ぐための「複数人でのバージョン管理を用いた標準的な開発プロセス」を確立することも裏の目的とする。

## 2. システム全体構成（アーキテクチャ）
Databricksのベストプラクティスである**メダリオンアーキテクチャ（Bronze / Silver / Gold）**を採用し、データレイクハウス上に堅牢なデータパイプラインを構築すること。

## 3. 機能要件
データパイプラインおよびダッシュボードが満たすべき具体的な機能は以下の通りとする。

### 3.1 データ取り込み機能（Bronze層）
*   **入力元:** 指定のストレージ（DBFSまたはUnity Catalogボリューム）に配置されたEC生データ（注文、顧客、商品などのCSVファイル群）。
*   **処理:** 生データに変更を加えず、そのままDeltaテーブルとして保存すること。履歴の追跡や再処理が可能な状態にしておくこと。

### 3.2 データクレンジング機能（Silver層）
*   **入力元:** Bronze層の各テーブル。
*   **処理:** 分析に耐えうる品質にデータをクレンジングすること。
    *   欠損値（NULL）の適切な処理（補完または除外）。
    *   データ型の変換（例：文字列の注文日時をTimestamp型に変換）。
    *   個人情報（PII）や分析に不要なカラムのマスキング・除外。

### 3.3 データ集計機能（Gold層）
*   **入力元:** Silver層の各テーブル。
*   **処理:** ビジネス要件に合わせた集計データマートを作成すること。最低限、以下の要件を満たすテーブルを生成すること。
    *   **月別・カテゴリ別の売上集計:** 売上トレンドを可視化するためのベースデータ。
    *   **顧客属性別の購買傾向:** （例：地域別のアクティブユーザー数など）。
    *   テーブル間のJOINや、GROUP BYを用いた集計ロジックを実装すること。

### 3.4 ワークフロー自動化機能（Databricks Workflows）
*   Bronze → Silver → Goldの順番で、依存関係を保ったまま処理が実行されるジョブを定義すること。
*   手動実行（Run Now）でエンドツーエンドの処理が正常に完了することを確認すること（将来的な日次バッチ処理を想定）。

### 3.5 可視化機能（Databricks SQL）
*   Gold層のデータを参照し、以下のチャートを含むダッシュボードを作成すること。
    *   月別の全体売上推移（折れ線グラフ）
    *   カテゴリごとの売上構成比またはランキング（棒グラフまたは円グラフ）
*   ダッシュボードは、SQLの知識がないビジネスユーザーでも閲覧・理解できる直感的なレイアウトにすること。

## 4. 非機能要件
*   **データフォーマット:** 全てのテーブルはパフォーマンスと信頼性に優れたDelta Lakeフォーマット（Deltaテーブル）で保存すること。
*   **保守性:** 処理のベタ書きを避け、共通で利用する関数（日付変換など）は別ファイル（モジュール）に切り出し、呼び出して使用する構成を検討すること。

## 5. 開発環境・プロセス要件（必須ルール）
本プロジェクトは、2名体制での共同開発を前提とし、以下のGit連携プロセスを厳守すること。

*   **バージョン管理:** Databricks Repos（Gitフォルダ）を使用し、リモートリポジトリ（GitHub等）と連携すること。
*   **並行開発:** 開発担当者は直接 `main` ブランチを編集してはならない。必ず機能ごとにブランチ（例: `feature/bronze-silver` や `feature/gold-agg`）を切り、独立して開発を進めること。
*   **コードレビュー:** `main` ブランチへの統合は、必ずPull Request（PR）を作成し、もう1名の担当者がコードレビューを行い、承認したうえでマージすること。
*   **本番稼働:** Databricks Workflowsで実行するジョブは、個人のワークスペースのコードではなく、Gitリポジトリの `main` ブランチのコードを直接参照して実行する設定とすること。

## 6. スケジュールと納品物

*   **納品物:**

    2.  Databricks Workflowsのジョブ設定
    3.  Databricks SQL上のダッシュボード
