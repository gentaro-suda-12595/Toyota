# グローバル人事データ基盤構築およびガバナンス演習 要件定義書

## 1. プロジェクト目的
本プロジェクトは、高度な機密性を持つグローバル人事（HR）データの処理パイプラインを構築し、Databricks Unity CatalogおよびDelta Lakeの高度な機能を活用したデータガバナンス・障害復旧プロセスを確立することを目的とする。

## 2. チーム体制と役割
*   **Aさん（データエンジニア / 管理者）:** パイプライン構築、スキーマ管理（Schema Evolution）、変更データキャプチャ（CDF）の実装、アクセスポリシー（行フィルター・列マスク）の実装を担当。
*   **Bさん（データアナリスト / 監査役）:** 差分データの分析、障害シミュレーションおよびTime Travelを用いた復旧作業、アクセス制御の監査・検証を担当。

## 3. 技術スタック・前提環境
*   **プラットフォーム:** Databricks (Premium層またはEnterprise層必須)
*   **ガバナンス:** Unity Catalog (有効化済)
*   **ストレージ・フォーマット:** Delta Lake
*   **言語・API:** PySpark, Spark SQL, Databricks CLI / Workflows
*   **バージョン管理:** Git (GitHub等)

## 4. データアーキテクチャ (メダリオンアーキテクチャ)
*   **Bronze層 (`bronze_hr_employees`)**
    *   **役割:** 外部ソース（モックデータジェネレーター）からの未加工データの格納。
    *   **スキーマ要件:** `emp_id` (文字列), `name` (文字列), `department` (文字列), `region` (文字列), `salary` (数値), `ssn` (マイナンバー/文字列)。※後続フェーズで `bonus` カラムを追加。
*   **Silver層 (`silver_hr_employees`)**
    *   **役割:** クレンジング済みデータ。運用上のマスタデータとして機能する。
    *   **要件機能:** Change Data Feed (CDF) の有効化、動的アクセス制御（行フィルター・列マスク）の適用。
*   **Gold層 (`gold_dept_metrics`)**
    *   **役割:** 分析用の集計データマート。
    *   **要件機能:** CDFを活用した増分更新 (`MERGE INTO`) による部署別・リージョン別集計。

## 5. ガバナンスおよび運用ルール
*   **Infrastructure as Code (IaC):** 行フィルターや列マスクの関数定義、テーブルへの適用（ALTER TABLE）など、すべての操作はUIを使用せずSQL/Pythonコードとして記述し、Gitでバージョン管理すること。
*   **自動化:** Databricks Workflowsを使用し、Gitの `main` ブランチを参照（`source: GIT`）する形でジョブを実行すること。
*   **権限の分離:** 設定者（Aさん）と監査者（Bさん）のアカウントを明確に分け、権限分離（セグリゲーション・オブ・デューティ）を検証すること。
